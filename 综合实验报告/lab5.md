## 四、系统调用流程分析

一个典型的系统调用（以 `sbrk` 为例）执行流程如下：

用户程序 sbrk(n)

   ↓

用户态系统调用桩（usys.S / usys.pl 生成）

   ↓

ecall 指令

   ↓

uservec（陷阱入口，保存寄存器）

   ↓

usertrap → syscall

   ↓

sys_sbrk（内核具体实现）

   ↓

返回值写回 a0

   ↓

恢复现场，返回用户态

在该过程中：

- 系统调用号通过寄存器 `a7` 传递
- 参数通过寄存器 `a0` ~ `a5` 传递
- 返回值通过 `a0` 返回给用户态

## 五、sys_sbrk 的功能与设计

### 1. 功能说明

`sbrk` 用于 **调整进程的数据段（堆）大小**：

- 参数 `n` 表示堆空间的增量（可以为正或负）
- 返回值为 **调整前的堆顶地址**
- 若调整失败，返回 `-1`

用户态常通过 `malloc` 间接调用 `sbrk` 来申请堆内存。

### 2. 数据结构基础

在 xv6 中，每个进程使用 `struct proc` 维护其地址空间信息，其中：

- `p->sz` 表示当前进程已分配的用户空间大小
- 堆的增长本质上是修改 `sz` 并分配/回收页表映射

## 六、sys_sbrk 的具体实现

### 1. 参数获取

`sys_sbrk` 只有一个整型参数，通过 `argint` 从用户态获取：

int n;

if (argint(0, &n) < 0)

​    return -1;

### 2. 记录原堆顶地址

根据实验要求，`sbrk` 需要返回 **调整前的堆顶地址**：

uint64 oldsz = myproc()->sz;

### 3. 调整进程地址空间大小

调用 xv6 已有的 `growproc` 函数完成地址空间扩展或收缩：

if (growproc(n) < 0)

​    return -1;

`growproc` 内部会根据 `n` 的正负：

- 分配新的物理页并更新页表（n > 0）
- 回收页表和物理页（n < 0）

### 4. 返回结果

若执行成功，则返回旧的堆顶地址：

return oldsz;

## 七、实验测试与结果

### 1. 用户态测试代码

// in initcode.c

#include "sys.h"

int main(){    

long long heap_top = syscall(SYS_brk, 0);    

heap_top = syscall(SYS_brk, heap_top + 4096 * 10);    

heap_top = syscall(SYS_brk, heap_top - 4096 * 5);    

while(1);   

return 0;}

### 2. 测试结果

- `sbrk` 返回的地址与预期一致
- 写入新申请的内存不会触发异常
- 多次调用 `sbrk` 后，进程内存空间持续增长
